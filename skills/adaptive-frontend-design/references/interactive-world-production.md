# 需求确认后的交互世界制作路线

> 公开分发版：相对原项目指导做了去标识与可移植性改写，来源与第三方许可见[来源](../SOURCES.md)。

用于需求对话后已决定制作完整可交互3D网站的任务。主入口与[设计对话](design-dialogue.md)负责先理解需求并选择路线；本页不让所有网站默认变为3D。“一句话”指用户可用自然语言发起需求，Agent承担后续澄清、选型、制作与验收，不指一次调用、无需回答或保证固定时间/效果。

## 1. 从内容动作选择交互形式

先写清访客通过操作要看到、理解或完成什么。用户未指定具体机制时，按已确认目的推荐相称方向，不把机制清单交给用户填，也不沿用上次的汽车、配色或模型舞台。

| 主要内容关系 | 可以采用的交互 | 必须形成的结果与代价 |
|---|---|---|
| 地点、地标与藏品分布 | 场景查看、步行/飞行/轨道探索、地图直达；驾驶只在题材适合时采用 | 知道所在位置、找到内容、进入与返回；自由度增加也增加迷路和输入成本 |
| 物件结构、材料与部位 | 旋转近看、部位聚焦、配置/照明变化；确需看内部时再拆解 | 当前取景能看清变化的部位，说明与选择一致；模型须有相应结构和材质 |
| 过程、时间与因果叙述 | 章节、滚动镜头、形体/环境转换、媒体交接 | 每段新增认识在画面中有依据，可停读、倒退或直接到章节；不能只给同一模型换背景 |
| 对象间的组合、次序与关系 | 拖放、装配、布局或可解释的演化 | 操作产生真实结果、约束与复位，不把装饰拖动或假保存当完成 |
| 数据、分类与空间分布 | 选择、筛选、时间/层级切换、关联聚焦 | 保持数据身份与含义，细节可读，能返回全貌；3D不能掩盖必要比较 |
| 输入驱动的艺术体验 | 局部形变、粒子/光场/流体等可扰动表现 | 输入、释放后演化与内容关系可见，提供安静阅读和恢复；2D实验不冒称可漫游3D |

这些是内容动作的机制候选，不是六套固定外观或每站必做项目；整站主导组织关系沿用[世界动效](immersive-world-motion.md#整站动态先选组织关系)，跨页寿命与可寻址内容按现有相应章节处理，不再另造一套分类。摄影、材质、字形、色场、场景密度和观看距离仍按[整体视觉](global-visual-direction.md)决定。3D体验也可有较大正文、紧凑比较与稳定控件，不统一成模型加参数面板。

## 2. 让多种效果共同解释一件事

把保留的效果连成短因果链：**用户动作 → 可辨对象/空间变化 → 注意力交接 → 新内容或结果 → 继续与返回**。按实际内容组合环境运动、对象动作、相机、材质/光、文字和界面过渡，不按数量配额叠加。用户明确要求丰富效果时，说明这些变化分别承担什么，不只增加hover或随机粒子。

例如藏品展览可用空间地标组织查找、近看镜头显示细节、材料高光解释表面、阅读层提供故事；器物查看可用旋转与照明显示轮廓、部位标记连到说明、退出恢复总览。它们不需要汽车或相同的镜头、模糊、颜色。声音仅在当前授权与设备能力内使用，不能成为唯一信息渠道。

真正的全景/沉浸承诺要覆盖主要路径，不能止于一个首屏模型和后续无关联卡片。长文可进入稳定DOM层，连续性靠对象身份、观看关系与返回维持。360照片/预渲染影片与真实几何探索能力不同，按本次目标准确命名。

### 沉浸感要在画面与操作中成立

当已确认的目标是沉浸式3D或强动态体验，把访客在何处、看向什么、操作怎样改变体验写成可执行的画面安排。先决定空间/视点与时间怎样帮助这次内容，再决定效果；可旋转模型、会滚动和有灯光只是能力，不能单独证明沉浸感。沉浸也不要求自由漫游、写实画面或一直运动。

- **空间有可感知的关系。** 用与题材相称的前中后景、遮挡、尺度参照、视差、接触与投影建立远近和重量。环境围绕主体组织方向、节奏与发现，不能只是无关背景。风格化或抽象场景同样需要自洽的空间线索；不为凑层数挡住内容。
- **镜头决定看见与发现。** 给开场、探索/操控、近看和停读各自合适的距离、视线与留白。移动有明确去向，途中轮廓、地平/空间锚点、焦点与阅读区要成立；避免镜头穿模、突然变焦、恒定绕圈或与手动输入争夺。用户停下时能看清，继续时有方向，窄屏重新取景。
- **光与材质讲同一种视觉语言。** 先在最终取景中校准轮廓、明暗层次、表面粗糙度/反射、色彩与接触关系。釉面、金属、布料或抽象能量场应有与其角色相称的响应；缺少几何、纹理或环境依据时先补资产，不用高亮、泛光、雾或景深盖住不足。后期只保留对主体可辨性有帮助的部分。
- **动态有主次和因果。** 区分低干扰的环境生命感、直接跟手反馈、对象主动作、注意力交接和稳定停留。将相关变化绑定同一动作或进程，让用户能分辨自己造成了什么；背景与标题不抢主动作，长文/比较期间允许安静。多个系统一起运动不意味着它们必须同频或同幅度。
- **反馈来自当前世界。** 指针、拖动、滚动、选择或按压影响当前对象/空间，并产生可见的重心、形体、波纹、光线、粒子或其他符合题材的结果。不是所有题材都需要物理，声音也只是授权范围内的辅助；反馈不能仅是面板数字或按钮变色。

### 把效果写到可以制作的程度

对当前承诺的关键效果，简写“作用对象/范围 → 驱动变量 → 视觉变化 → 停止/释放与恢复 → 内容出口”，并选能实现该变化的素材与渲染方法。只写“高级光影、流体、电影镜头”不构成制作依据。以下是可迁移的设计候选，不声称复现原站算法或每站效果清单：

| 当前视觉意图 | 可以实施的关系 | 实看时排除的失败 |
|---|---|---|
| 空间中逐步发现内容 | 场景尺度/遮挡与相机轨迹配合；视差或雾按当前世界距离组织，地标引导近看 | 主体一直很小、过场找不到目标、雾只像半透明遮罩 |
| 材料随观看与操作呈现细节 | 实际表面/法线、粗糙度与光源/环境方向响应；观看角度变化时仍能解释同一部位 | 只有整体改色、高光烧白、纹理漂浮或局部说明没有可见依据 |
| 表面或场被输入扰动 | 在合适坐标中维护扰动位置、半径、强度及随时间的释放；选择网格形变、shader、粒子或2D等合适实现 | 光标附近随机抖动、离开后骤停/失控、响应与画面位置错开；2D效果误称可漫游3D |
| 主体带着内容经历变化 | 镜头、对象动作/形变、环境与文字围绕同一语义阶段协作；进度可暂停或反向时仍有定义 | 同一物体空转、只是换标题、强制等待后才能访问内容 |
| 输入带来有重量的响应 | 跟手阶段保持可控，释放后用相称的阻尼/有限演化延续，再到可操作状态 | 动作被过量平滑拖慢、抖动、没有收敛或连续输入丢失 |

例如海洋主题可从空间尺度进入、靠近对象、扰动局部流场，再稳定呈现结构；陶器主题可从器形轮廓、掠射光揭示釉面与手作痕迹，进入部位近看再回到整体。两者不共享固定特效、镜头或背景，仅共享“操作引发可理解变化、画面接住注意力”的方法。具体实现按现有[运动语言](motion-language.md)、[交互接续](interaction-craft.md)和[Three.js工作流](threejs-workflow.md)，不另建同义状态框架。

## 3. 先用真实材料做代表切片

内部用一小段制作依据约束执行：主题与读者；主对象/空间参照；主要操作与结果；直接入口和返回；拟用的动态分工；素材/运行条件；宽窄重排与未测项。它不是用户必须填写的长表。

先准备会决定判断的模型/图像、真实标题、材质与光线。复用素材须逐项核对许可、来源和可编辑原件；导入后核对单位、轴向、根/部件、UV/材质类别与需要的结构。一个GLB可含独立模板、预放实例或不同材质语义，加载成功不等于可以整组直接使用。具体资产与显示链按[素材](media-and-assets.md)及[Three.js工作流](threejs-workflow.md)处理。

纹理、凹凸和后期增加后，仍在总览与局部检查材料是否符合预定角色；条纹、反射或噪声让形体读错时先调尺度、对比或几何依据，不以效果已启用判断材质完成。高级显示分支在目标环境出现异常时，定位该分支并采用能兑现当前主张的表达，同步修改说明；一次透射失败不成为所有项目禁用透射的规则。

先实际看一段“进入 → 主要操作 → 内容/结果 → 返回”的最终尺度画面，再扩展依赖其资产、构图或机制的部分。字体遮住主体、表面被淹没、对象仍是示意体或说明指错位置时先修对应关系，不用技术通过冒充美术完成。其他已明确且独立的工作可以继续。

## 4. 让场景、输入与内容共享身份

本路线选出的探索、查看、过渡、阅读与恢复，落实到同一内容身份。抵达点/可操作区域、途中改选和提前阅读意图按[语义状态](scene-content-continuity.md#同一份语义状态明确各自进度坐标)；完整相机接管按[取景交接](scene-content-continuity.md#取景交接保留完整画面)；环境、对象、输入与过渡按[时钟分工](scene-content-continuity.md#给环境输入与交接分配时钟)；入口隐藏、输入隔离和可见焦点返回按[空间入口与正文](scene-content-continuity.md#把空间入口接到同一篇正文)。这些由对应主文件维护；具体跟手与打断继续用[交互接续](interaction-craft.md)。

若用户操控角色或物件，让该对象对加速、转向、停止和接近内容给出题材相称的姿态、形变、表面或光等反馈；不能只更新坐标或界面数字。跟随镜头的位移与转向要接续，移动方向应与当前可见视线/明确控制约定一致。实际走持续移动、快速环顾后继续前进、松手收束，不照搬某次惯性、灵敏度或阈值；局部模型查看不因此增加漫游角色。

碰撞、物理、声音或持续模拟只为内容需要添加。对导入对象校准可见表面与碰撞/命中范围；恢复到本次任务合理的安全状态。驾驶案例中的轮轴、按键、重生和物理参数不迁移为所有3D网站的合同。器物可以回总览，装配可撤销，数据场可清除筛选。

## 5. 运行交付与主Agent验收

先接通一条真实内容路径，实际使用后再扩展同类目标。按当前已知接口分工；同文件和依赖写入串行。适用工具、框架、物理/后期库由项目与素材决定，不强制换栈、安装新系统、调用其他Agent或新增费用。

启动可运行预览并核对实际入口，再做实屏检查。开发工具受当前环境限制时，可用等价的已构建预览继续验收；要记录已用入口与失效部分，不扩大系统权限、假造进度或把本机临时端口写成长期依赖。

### 连续体验与交付证据

完成初版后，Agent主动按正常入口自走“发现 → 操作 → 停留 → 返回”，对照已确认的体验意图；允许研究原参考时只复看能解决当前疑点的片段。先指出实际差距及可能原因，再修最有影响的关系并复走同一路径：例如空间融成平面、操作物缺少身体反馈、镜头与输入脱节，不能统一回答“多加动效”。保留有效部分，不设固定迭代次数，也不以自查代替本人接受。

沉浸式承诺同时检查**视觉体验**与**功能路径**。在真实窗口按正常速度看一条“建立空间 → 用户操作 → 关键变化 → 停留/阅读 → 继续或返回”的连续路径，观察中段与释放之后；不要用起止截图、功能通过或技术栈名称替代。先修最破坏当前主张的问题，再扩展依赖它的效果：空间平、主体弱、材质失真、镜头无目的、反馈没有因果或动态抢夺内容，分别回到构图/资产/光照/编排原因。

记录所承诺的表现实际在哪里可见、用户怎样触发和观察到什么；原速观察、按需录屏及未测边界统一按[运动验收](motion-language.md#正常速度观察与录屏)。作者自查、运行验证与用户对沉浸感的接受分别说明。降低质量时优先保留主体轮廓、空间方向、操作反馈和内容可读性，再减次要环境与后期，不把低档变成失去原承诺的另一种页面。持续流畅与设备负担要实际测量。

最低有意义的验收围绕本次承诺：

- 主体、材料/光、文字与控件在真实窗口中协调；看必要中段，不只看起止点。
- 原生指针完成主要3D操作/命中，键盘及当前要求的输入另核对；程序派发事件、仅键盘或UI颜色变化不替代相应路径。
- 地图/列表直达、途中改选、合理输入的排队/接管/取消、内容打开、关闭和继续指向同一对象；被阅读层盖住的控制不穿透。
- 宽窄按内容重排取景与控制，重要信息和退出可达；核对当前目标标签、实际DOM窗口与canvas边界后记录尺寸，设置了视口或面板打开返回queued不证明目标已改变或显示。窗口模拟、指针点击和实体触摸分别说明。
- 必要加载/失败/恢复路径、减少动态与当前资源所有权按实际风险检查；持续性能、听感与GPU恢复只按真实测量说明。

主Agent核对最终画面与使用路径，汇总测试和协作者结果。交付运行入口、指定版本、素材说明、代表画面与未测项；用户未反馈时不记整体接受。本方法不保证任意一句话必然产生相同质量，也不把汽车项目变成所有新任务的起点。公开来源与归属见[来源说明](../SOURCES.md)。
