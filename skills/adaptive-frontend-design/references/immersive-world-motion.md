# 全局动效与3D世界：身份、导航、内容使用同一空间

> 公开分发版：相对原项目指导做了去标识与可移植性改写，来源与第三方许可见[来源](../SOURCES.md)。

在当前方向明确需要持续3D场景、空间导航或跨章节镜头时读取。公开来源包括 Active Theory、Immersive Garden、Bruno Simon 的作品、作者文字和固定版本源码；不是完整复刻教程。普通阅读页、表单或局部hover不加载，也不自动引入游戏、AI聊天或多人服务。

场景需要连续接入正文、近看切换或内容重排时，进一步读[场景与内容连续衔接](scene-content-continuity.md)：处理完整取景、进度坐标、活动时钟、空间入口与窄屏阅读，不把同一个canvas当作连续性的充分条件。

## 整站动态先选组织关系

用户明确要整站动态时，先选主导关系，再组合其他表达；三类不是功能配额，也不是三套固定版式。

| 主要内容怎样被访问 | 适合的动态组织 | 制作时真正要决定的事 |
|---|---|---|
| 自选地点、反复探索、从不同入口接近内容 | 持续的可探索世界 | 地点之间的关系、可辨认地标、可操作物与环境的区别；直接导航和自由探索怎样抵达同一内容 |
| 需要先后看清一个变化、过程或故事 | 镜头随内容推进的旅程 | 主体经历了什么、何时换取景或媒介、停下时有什么可读；直接选章节不依赖从头播放 |
| 作品、档案、文章需要不同阅读尺度 | 排版、图形与媒体共同运动 | 同一内容在概览、查找、近看和详情里的关系；保留可辨认导航，不把静态正文强行变成3D |

持续世界的丰富感也来自场所、物件与内容关系：相邻地点有可辨认差异，操作结果在这个世界中有依据，环境承担气氛，入口承担明确动作。不要让每个装饰物都像可点击热点，也不要只在同一模型背后轮换标题。运动可以从空间让给项目媒体，再让给稳定正文；整站性看关键节点与交接是否成立，不能以每屏ticker或旋转物数量判断。

三类组织可以组合，跨页世界与当前内容的寿命分别处理。镜头、时钟、输入和阅读规则沿用下文及[场景连续性](scene-content-continuity.md)，不另建同义流程。

### 跨页世界和当前页面各自保留什么

若体验跨越真实页面，先按当前框架明确三种寿命：跨页保留的世界/渲染器与身份，随当前内容更换的场景片段/媒体，随页面或阅读层生效的入口/输入/订阅。它们可以由不同层持有；不强制单例或新状态库。页面替换只清理该页拥有的实例，不能误销毁共享世界；保留世界也不意味着常驻全部模型、视频和隐藏热点。沿用[Three.js生命周期](threejs-workflow.md)处理共享资源。

项目A→资料页→项目B可以延续共同空间身份，同时替换A的内容和操作归属；再次返回时根据语义目的地恢复，不默认保留全部实时状态。正常跨页、途中改选与历史返回都要让当前内容、可见入口和输入所有者一致。实际检查旧页热点不再能激活、新页操作可用、共享世界未被意外重建；保留一个canvas节点或URL已改变只能证明其中一项。需要分享或刷新时，继续按[内容寻址](scene-content-continuity.md#内容寻址与浏览器历史)建立入口。

## 1. 先说明世界如何帮助用户

先给主体、环境、导航和内容分别分配职责。持续3D对象可以承担品牌身份，空间地标可以说明所在位置，镜头可以把注意力交给项目；长说明仍需要稳定可读的入口。若世界不能帮助理解、辨认或探索，先简化表达，不用粒子数量证明设计价值。

对有叙事推进的页面，用当前内容写一条短运动安排：**输入 → 保留的空间锚点 → 镜头/形体变化 → 可读内容 → 直接入口与返回**。只为实际存在的阶段补资产和动作，不强制固定章数或统一节奏。

同时决定场景每一段如何占据页面：承担开场、与文字共享空间、靠近一个部位，还是让出稳定阅读区。持续世界可以改变出现的范围，连贯不要求始终固定在同一个模型框里。[Lusion首页](https://lusion.co/)包含宽幅物件群、放大的reel、项目媒体和接管视口的宇航员场景；这支持按内容改变场景角色，不构成必须全屏、必须长滚动或连续流畅的通则。独立查看器、参数比较等任务仍可保留稳定框架。

全局动效的承诺要落在这些交接上。正文说的是新用途或证据，场景就应显出相关内容或让合适媒介接过来；同一模型只换角度、换底色，而认识没有推进时，先补材料或改内容顺序。实际素材、字体和段落一起观看后再扩展运动，不能用模型ID持续、动画调用成功或GPU检查代替整站视觉判断。

例如工作室首页从远景标志到项目概览：背景维持空间，标志转换位置/尺度，标题获得稳定阅读区，作品链接可以直接选，进入详情后仍知道从何处返回。不是给每个段落另建一个无关3D舞台。转场中途要看主对象轮廓、文本遮挡与真实命中区域，不能只对比起点终点。

也可以让同一主体逐步经历动作、环境和结果。Lusion的[作者访谈](https://www.commarts.com/project/36283/lusion)说明角色随滚动穿越环境、可倒退，并有按压改变节奏的操作。作者描述与网站部署可能处于不同版本，不把历史文字升级为当前算法或新项目验收。迁移时先写“谁经历什么、用户如何改变、何时可读”，再设计镜头和模拟。

## 3. 让镜头所有权能交接

对探索型世界，先将设备事件归一为动作，再声明动作在哪些情境可用。Bruno的[Player动作类别](https://github.com/brunosimon/folio-2025/blob/41046b57eeed8d156d9c3fd7fa259900baef7816/sources/Game/Player.js#L218)区分wandering/racing/cinematic；这提供的是组织方式，不要求新项目照搬类别名。

通用接管按[完整取景交接](scene-content-continuity.md#取景交接保留完整画面)处理；以下保留来源中的具体组织例子。Bruno的[View](https://github.com/brunosimon/folio-2025/blob/41046b57eeed8d156d9c3fd7fa259900baef7816/sources/Game/View.js#L584)用手动pan解除tracking、移动动作恢复tracking；该组织方式不构成跨设备或帧率稳定性保证。展品查看器可以改为“拖动近看 / 回总览”，无需驾驶。

相机交接必须取包含手动偏移后的真实相机，而非仍留在预设位置的目标状态。手动持有期间停止程序追赶；交回后从该姿态接续，再逐步恢复环境摇移。否则名义上切了模式，仍会暗中漂移或返回跳镜头。用真实拖动、持有和退出核对，不将某次参数用于所有相机。

阅读输入隔离、导航覆盖旧过渡、抵达与内容可用分别按[语义状态](scene-content-continuity.md#同一份语义状态明确各自进度坐标)及[空间入口与正文](scene-content-continuity.md#把空间入口接到同一篇正文)实施。具体运动核继续用[交互接续](interaction-craft.md)，渲染实现用[Three.js工作流](threejs-workflow.md)。

恢复按实际故障分层：轻微姿态问题可局部自救；用户卡住有显式救援；迷路/越界可回最近安全点。Bruno的[Player恢复](https://github.com/brunosimon/folio-2025/blob/41046b57eeed8d156d9c3fd7fa259900baef7816/sources/Game/Player.js#L345)有等待3秒尝试翻正、Unstuck和重生入口；没有核对最近点算法或物理安全性。普通展览只需回当前展品总览，不为演示恢复而增加物理系统。

## 4. 按依赖顺序推进，而非各自启动ticker

当多个动效读取同一世界状态，先画本项目所需依赖：**输入意图 → 模型/物理状态 → 位置与区域 → 相机焦点 → 视觉/媒体/声音 → 渲染**。无物理或声音则省略相应环节。Bruno的[Game loop文档](https://github.com/brunosimon/folio-2025/blob/41046b57eeed8d156d9c3fd7fa259900baef7816/readme.md#L22)提供了这种顺序的作者依据，不证明新项目的逐模块调度正确。

每帧先更新被依赖的状态，再让相机、热点或区域反馈读取；否则会出现跟随落后一轮、画面已到但热点仍指旧位置的问题。各系统可有不同频率，但读取哪一份状态应明确。隐藏页签、暂停、长帧恢复按当前物理/解析动画分别处理，不能把所有时钟统一粗暴截断。例如把累计绝对时间当作每帧增量，会使不同帧率下的动态速度失真；每个系统明确使用增量、活动累计时间或有限过程进度。

**暂停绘制不等于停用界面。** 转入资料或覆盖层时，同步处理DOM热点的点击、键盘焦点和辅助技术暴露；不要把收起入口的逻辑只放在会被跳过的帧循环中。aria-hidden不是交互停用，可按平台使用隐藏、inert或框架的等价机制，恢复后再核对投影和命中。用可见导航附近的Tab/反向Tab及确认键检查，避免“画面已盖住，旧热点仍能激活”。按当前宿主选合适机制，不强制所有项目使用同一API。

## 5. 资产管线参与造型和性能决策

IG作者说明服务端**KTX**压缩、尽可能打包纹理通道、模块化模型变体，以及gltf-transform、自写JS/Blender脚本自动导出。文中未指定KTX1/KTX2、编码器或具体通道映射，不补写。其[作者访谈](https://www.commarts.com/webpicks/immersive-garden)明确概览与Backstage分层、one-click access。浮雕美术质量与这种资产工作相关，调JS曲线不能补出缺失几何。

实施时保留可编辑原件，生成可追溯的运行时派生物；Bruno的[资产说明](https://github.com/brunosimon/folio-2025/blob/41046b57eeed8d156d9c3fd7fa259900baef7816/readme.md#L116)也是导出后单独生成压缩文件。为实际资产记录用途、变体、单位/原点/UV、通道语义、格式/加载器、尺寸和许可，再选择压缩。换模型仍沿用合适的对齐与加载合同；不能把一个模型的尺寸和相机常数复制给所有变体。

纹理下载体积、解码/GPU内存、画质各自测量；“用了KTX”不证明预算通过。数据通道不能误当颜色，压缩后要在最终镜头与光线下看轮廓、法线和高光。加载/解码失败要保留可读项目与重试；禁止假进度掩盖未知总量。材质/颜色/版本细节由Three.js工作流负责。

## 6. 迁移时检查真实路径

先用当前项目的一条完整切片验证持续锚点、直接选项、中途改选、查看接管、阅读与返回；据此扩展同类章节。若主要承诺是动态形变或雕塑质量，还必须在自己的资产上验证该承诺，不能仅用状态测试通过替代。

核对实际视口、主体面积和阅读安全区；窄屏可换镜头和文字顺序，保留直接访问。低动态/静止路径保留内容和方向，不只是把CSS缩成1ms。记录浏览器、设备和未测输入；截图证明状态，不能单独证明连续手感、转化收益或获奖作品质量。

公开源码和作者说明支持特定组织方式，不证明新项目已实现商业浮雕/粒子管线、驾驶物理、服务器或相同材质质量。来源与归属见[来源说明](../SOURCES.md)，按新项目的真实路径记录已测与未测范围。
