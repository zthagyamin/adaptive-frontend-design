# 视频与运动：把变化编排成可理解的内容

> 公开分发版：相对原项目指导做了去标识与可移植性改写，来源与第三方许可见[来源](../SOURCES.md)。

媒体条件方法；具体片段、光线和节奏必须用当前作品验证。研究没有证明通用FPS或普遍最优时长。

镜头语言、连续节奏、声音与影像配合、光线/调色和多比例艺术方向，都需要完整原速序列与明确视觉判断。播放成功、实际运动和大画幅本身不能证明视觉质量；以下方法约束内容职责和完整行为，表现质量仍由当前作品检验。

适用于交互状态变化、滚动编排、产品影片和多幕叙事。功能站只读取当前行为所需部分；明确要求运动或视频叙事的任务，应提供相称的实际媒体与运行实现。先实现能观看、能操作的关键页，经用户审美审核后再扩展整站。

补充条件、代价和验收见[条件规则补充](conditional-design-rules.md)的 `VM-*`，来源见[来源说明](../SOURCES.md)。把作者明确说明、页面观察和待验证的迁移假设分开；本方法不反称为源站已实现的算法或新作品验证。

## 先给运动一项内容职责

`VM-01`：在设计执行单里写“什么内容发生什么变化，用户因此能理解/完成什么”。运动可以解释对象结构、呈现状态因果、连接前后位置、表现角色行动或建立品牌情绪。仅为吸睛而持续运动时，先说明它为何值得占用注意力。字体、色彩、素材、光线、空间和运动服从同一主线，不把各站的亮点拼成特效目录。

| 内容任务 | 适合的职责与实现 | 空间作用与代价 | 反例 |
|---|---|---|---|
| 计数、展开、保存等功能状态 | 让结果变化、对象身份与操作反馈相连；运动结束不决定数据是否保存 | 给变化留出局部空间，不推走仍在操作的目标 | 高频输入不应每次播放长入场 |
| 产品外观、内部结构、使用场景 | 分镜分别解释不同层级；图文与控件指向同一能力 | 主体负空间支持轮廓和解释，章节距离标记问题变化 | 规格比较应能直接看数据，不能强迫逐幕观看 |
| 文章中的可试原型 | 解释点亮对应状态，提供同名控制与复位 | 桌面可并列，手机可内联，保留关系而非固定列数 | 宽代码或大画布可能需要切换模式 |
| 品牌短片、艺术作品 | 画面与声音本身可成为主内容，旁置简短作品信息 | 画廊式空域减少竞争，但增加遍历时间 | 紧急信息、结账或查找任务不靠影片解锁内容 |

来源：[AirPods](https://www.apple.com/airpods-pro/)、[免费原型](https://devouringdetails.com/prototypes/nextjs-dev-tools)、[New Life](https://sixnfive.com/projects/new-life/)、[Audi Rings](https://futuredeluxe.com/work/audi-rings)。这些案例支持内容职责与空间关系，不证明转化、学习效率或普遍更优。

## 先列状态，再写动画

`VM-02`：每个关键变化使用下面的最小状态表。动画可以连续，语义状态必须明确。源站取样中的点击回执或移动中截图不算抵达。

| 状态 | 实现决定 | 实际验收 |
|---|---|---|
| 初始/就绪 | 当前对象、已加载内容、可用操作是什么 | 初次加载与重新进入均可辨认 |
| 触发 | 点击、键盘、滚动还是章节推进；命中目标与提示一致 | 实际输入进入正确路径，按钮/焦点不漂走 |
| 中间 | 新旧内容是否并存；保留哪一个可操作 | 中间帧不显示错误事实、截断必要说明或制造双重提交 |
| 抵达 | 哪些数据、媒体、选中态、标签和可操作性同时成立 | 等到实际稳定状态再核对，不只看触发日志 |
| 打断 | 反向操作、快速连按、切页、隐藏页签时接受/合并/取消什么 | 不产生旧回调覆盖新选择、失焦或永久禁用 |
| 返回 | 回到哪个对象、位置、播放点和焦点 | 返回后上下文可辨认，核心操作仍可使用 |
| 复位 | 重置语义数据、视觉状态、计时器和可见性 | 改变后的内容真正回到初值，再做一次变化仍成立 |

为交互指定一个状态所有者；效果完成回调须核对仍是当前操作。按输入性质选择合并、取消或排队，不把全局禁用作为默认策略。用于装饰的过渡失败时，业务状态仍能抵达。具体时长、位移和 easing 作为**待验证实现起点**记录，通过真实内容和正常速度体验调整；来源观察没有建立可照抄的作者easing或通用最佳时长。

`VM-03`：原型、控制与解释共同指向当前对象。桌面可并置，窄屏把原型放在对应解释前后；按对象关系重排，不把全部原型统一移到页顶。在当前桌面与相关窄屏走“改变→折叠/展开→复位”的等价路径，核对数据、标签、颜色与控制，不以按钮反馈代替复位。

## 为视频写镜头单，而不是只放背景文件

`VM-04`：对承担叙事的视频，先为当前关键页填写短镜头单；可直接沿用剪辑已有镜头，不强迫重拍。

| 字段 | 必须决定 |
|---|---|
| 镜头目的 | 这一镜解释外观、结构、行动、对比还是情绪；只保留本段主问题 |
| 画面 | 主体、景别、机位、运动方向、光线、前后景与需要保留的轮廓 |
| 文案 | 进入时出现什么、到达后读什么；文字与主体的安全区与对比 |
| 声音 | 环境、音乐、旁白各自职责；信息是否也有字幕/文字，静音能否理解 |
| 节点 | 进入、关键揭示、停顿、离开、循环接缝；时长是片段实值或实现假设 |
| 用户控制 | 播放/暂停、声音、进度/章节、跳过、重播；按任务选择，控制名称明确 |
| 手机版本 | 保留全景还是另裁竖版，文字与控件是否移到画外；不能只等比缩小 |
| 失败 | 海报、文字摘要、重试和继续任务路径，保留当前上下文 |

示例（构造，非源站实测）：便携录音设备页先用全貌建立大小与使用朝向，再近拍输入旋钮解释控制，最后用真实场景说明单手操作。每镜对应一句可验证文案；手机近拍另取景，关键接口不被文字遮挡。若主题是艺术影片，可以让长镜头与声音主导节奏，但仍给用户可见的中断与返回。

[AirPods](https://www.apple.com/airpods-pro/)可用于研究同一产品的外观、结构与人物场景分工；[Vision Pro](https://www.apple.com/apple-vision-pro/)可研究组件层级与说明关系。影像不能据三维外观称为实时3D，也不能借当前链接为历史芯片或产品规格背书。

## 播放、手机与资源失败是设计的一部分

`VM-05`：按视频职责选择控件。背景氛围可以无声循环，但持续运动应有可发现的暂停方式；信息影片提供用户控制的播放、声音、必要的进度/字幕与重播。声音由用户明确开启；首次播放被浏览器拒绝时保留海报和播放按钮。文案不能只烧录在容易裁掉的画面里。

以真实可解码画面作为 loaded/ready 的依据。分别处理未请求、加载、缓冲、播放、暂停、结束、拒绝播放与资源错误。失败不留下无限转圈；呈现简短说明、重试与能继续任务的文字/静帧。切换源或章节时，不能让旧视频的结束事件提交新章节状态。按媒体语义保留用户的暂停选择，回到页面不擅自重启声音。

`VM-06`：宽屏和手机同时画构图。先标主体、字幕、长标题、进度与控制安全区，再定视频比例与裁切锚点。用真实长文案检查 390、320 和平板；横片可完整显示，也可制作竖版，但不能用一刀切的 `cover` 裁掉关键行动。滚动驱动时区分“阅读滚动”与“影片进度”，明示当前阶段；快速滚过、反向、跳到锚点与键盘导航都要抵达对应内容。避免一段无说明的巨大滚动空程。

主体负空间可以给标题、说明和动作留位置；画面空域与章节空域的代价不同。若空间只让 CTA 或关键信息更晚出现，缩短等待或给直接入口；若任务本身是观看完整构图，避免为压短页面挤成缩略图。作者作品中的影片比例只属于相应内容，不是全站默认比例。

## 验收动态，不用截图代替

`VM-07`：正常速度观看完整关键序列并记录打断与返回。交审交付可运行关键页、必要构图及状态证据；现有工具可取得且任务需要时保存正常速度片段。没有连续观察或录屏时明确缺口，不称连续流畅、60fps 或准确复现节奏，不要求用户新增录屏或校准。原生时钟推进只证明该采样段在播放。

记录捕获范围与对应源码版本。只捕获canvas或video可证明其中真实动态，不能称为含HTML控制、文字和指针的完整UI连续录屏；外围交互另给实际运行证据。后续修订不回填旧录像，未变化路径可复用，变化路径另验。

媒体时间推进、暂停和续播可证明相应播放状态，不支持整片运动质量已验收。首帧空白应区分未解码、离屏未请求、过渡与真正失败，不直接宣布失败或完成。

减少运动时保留同一信息、选择、进度和返回能力：按实际运动风险选择瞬时切换、短淡变、离散镜头或用户主动播放。强表现页面的默认版仍应完成所承诺的运动表达，不能以备用静帧代替正常版交付。这里是迁移要求，来源观察不能证明当前作品的减少运动路径。

最终核对：是否仍是一条主线；内容到达是否明确；手机对象/文案/控制是否同组；暂停、返回、复位、资源失败是否真实可用。技术通过与用户审美接受分开记录。
