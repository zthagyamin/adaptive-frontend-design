# 主动询问，确定能够实现和检查的设计方向

> 公开分发版：相对原项目指导做了去标识与可移植性改写，来源与第三方许可见[来源](../SOURCES.md)。

本流程适用于新建或整体改版且视觉方向未定的任务。用户当前要求优先。目的或本人要决定的方向仍不明时等待回答；已有方案、已接受页面的小修、明确复刻、或用户已授权直接选定方向时复用现有答案，不机械询问。

新需求只给一句话时，先提问理解它，不直接生成沉浸式世界。先完成下面的需求对话，再判断普通页面、功能界面、编辑叙事、局部3D或完整交互世界哪一种更合适。用户说“高级”“有动效”或使用本Skill，都不足以决定3D；已明确要3D时，仍需理解内容、交互目的与保留约束。用户已在当前任务回答、给足明确复刻条件或明确要求按既定方案直接执行时，复用这些信息，不重复开场。

## 先问影响设计的缺口

先读相关页面、已有品牌与材料，复用对话中已确认的信息。一次提出1–3个简短、容易回答的问题；能合并成一个核心选择就不分成多轮。通常覆盖下面实际缺失的部分：

- 给谁使用，来这里最先要理解或完成什么？用户只说“高级网站”时，这比字体颜色更先决定方向。
- 希望留下什么具体印象，有哪些喜欢/不喜欢的参考或必须保留的气质？给与当前内容相符的少量描述，避免让用户学习设计术语。
- 已有内容、图片/模型、品牌规范、目标设备、技术和维护条件是什么？只问会改变选择的约束，不让用户填通用长问卷。

用户希望点选、或需求尚难用术语表达时，优先用宿主支持的选择题：每题围绕一个会改变方案的决定，选项简短、可区分并保留自由说明；没有表单工具就用文字选项。推荐须有当前需求依据，不能通过默认选中把普通任务引向3D。把同阶段必要问题合为一组，已有回答不重问；信息足以出方案就给方向，不把题材、角色、颜色等拆成无止境的问卷。

问题可以给推荐选项，同时保留自由说明。不要用“你想什么风格”把全部设计判断交回用户，也不要从行业标签猜定深色、衬线、玻璃或3D。内容缺口会改变方向时先说明；仅影响细节的小假设可标明后继续。

## 给2–3个实质方向

先回答当前材料为什么需要这种表达：快速找资料/比较/读长文可以由清楚的DOM界面主导；看结构、尺度或配置可以选局部3D；需要探索、空间关系或明确的沉浸表达时再选交互世界。3D的维护、素材和操作代价与它带来的内容价值一起比较，不能先决定做3D再为它寻找用途。

使用同一目标和材料，提出少量可行、完成度相近的方向。每个方向用一小段讲清：

1. 第一眼看见谁，整页怎样从开场走到主要动作。
2. 字体字形、主要色场和明暗、素材光线/视角/裁切如何共同构成气质。
3. 有哪些值得保留的运动；3D若出现，用户通过它看到或做到什么。静态、DOM动效和实时3D都可成为完整方案。
4. 当前材料是否足够，手机怎样重排，制作或维护的主要代价是什么。

推荐一个方向，说明它为什么适合这次目的。方向差异应改变主体呈现、阅读路径、文字构成或互动方式；同一套大标题和卡片换三种颜色不算三个方向。不要用固定风格清单或随机选择代替对内容的判断。

把这些差异落在同一批实际内容上：让人能看见谁是主角、从哪里读、字形的重量、说明密度和素材观看距离怎样改变。遇到近期同质化反馈，避免给每个方向继续套上相同的淡色底、细分隔和微标签，只调整名称或色相。先修具体重复的关系，不要求方向越多越好。

例如同一份城市植物馆导览：一个方向可以让路线与地点组织阅读，另一个从不同叶形的并置比较进入，第三个从生长过程逐段展开。它们需要不同素材并支持不同任务；这不是所有展馆的固定三选项。

## 何时需要轻量草图

用户已能通过短描述做选择时直接推进。只有主体尺度、叠压、裁切、空间或动作关系难以比较时，才用同内容制作争议区域的轻量草图或可运行片段。保留标题、主体、关键动作和大色场即可；不为选方向先做三套完整网站，不要求录屏或校准。

运动无法靠静态草图说明时，使用现有工具做一条短动作切片；3D草图需要表现真实的空间关系，技术块状模型须标为草图，不能当最终商品资产。画面支持当前选择即可，不把草图形式固定成线框或高保真稿。

这里的“按需草图”只决定如何比较方向。选定方向后，强视觉任务仍按[代表画面检查](composition-craft.md#代表画面检查与扩展条件)用实际材料确认可制作性，不能以文字足够选方向为由跳过。该检查由Agent先做，不要求用户再次批准相同选择。

## 把选择变成制作依据

用户选择、合并方向或明确委托Agent决定后，用简短方案记录能约束实现的决定：

- 目标、主内容与最重要的动作；必须保留项。
- 首、中、末的阅读关系；视觉主轴、字体角色、大色场与素材条件。
- 关键动作的输入、主要变化、可读时刻、抵达与返回；3D的对象、光线、镜头和可操作结果。
- 窄屏的重排、必要退路与当前不能承诺的素材/能力。
- 如何在运行页看见这些决定成立；用户最终要体验的完整关键路径。

可以直接写在当前任务说明中，不强制新数据库或冗长设计合同。先实现代表方向的关键页，按方案看实际视觉和动态，再扩展；若执行发现素材或技术无法兑现，说明哪项受影响及可行替代，只重议相关选择。用户已决定的方向不因Agent喜欢另一套样式被悄悄替换。

## 来源与边界

方向联合设计、回看需求简报与具体视觉判断参考 Impeccable 和 Anthropic frontend-design，并按本方法的任务范围重新组织；不采用强制工具、固定代理、随机方向、字体禁令或统一比例。来源、固定版本及许可见[来源与归属](../SOURCES.md)。页面语言与品牌由当前任务决定，中文和混排指导只在适用时采用。方法文本不证明任何 Agent 已实际执行，最终效果仍由运行页检查与用户反馈判断。
