# 实时空间路线

> 公开分发版：相对原项目指导做了去标识与可移植性改写，来源与第三方许可见[来源](../SOURCES.md)。

先确定用户要理解的对象、部件、尺度或环境，以及为什么需要自行操作视角或状态。产品查看、空间探索和抽象体验的界面密度与相机行为可以不同，不把所有Three.js任务做成孤立模型加旁边控制面板。

明确实时几何／视角／部件关系、素材来源和运行依赖。照片、预渲染视频、poster或canvas标签不能证明实时3D；作者文章、应用引擎与具体资源的许可分别核对。环境、材质、灯光与对象比例共同承担内容，不靠技术名词说明完成度。

控制和命中要让人知道可以操作什么、是否受理、改变了什么。遮挡、相机距离、长说明和热点不要互相争夺画面；局部信息、近景回总览、进入／退出及失败退路闭合，保留合理的当前配置。

在同一实际成功环境走完进入、探索、目标操作、局部与返回，检查宽窄布局和相应输入。真实几何变化、光照／材质观感、交互正确和本人效果反馈分别记录。只有任务需要的设备／触摸／性能主张才触发对应测量；缺少工具则说明未测，不用模拟尺寸冒充物理设备。

复用当前可用技术与工具，不为流程安装新模型或系统组件；需要新费用、权限或软件时先按当前授权处理。已有空间作品的接受仅覆盖相应作品，不证明新架构或本路线已全面验证；功能阅读的返回结果不外推为3D拾取或空间恢复收益。

实际制作空间或对象交互时读取保留的[实时空间实现细节](realtime-space.md)；使用Three.js／WebGL实施或调试时再读[Three.js工作流](threejs-workflow.md)相关部分。方案或纯DOM调整不默认加载全部3D细节。
