# Three.js：从视觉目标到可验证的实时实现

> 公开分发版：相对原项目指导做了去标识与可移植性改写，来源与第三方许可见[来源](../SOURCES.md)。

用于页面中的 Three.js / WebGL 实现、改版或排错。先读取项目实际版本、渲染入口和素材，再选下列适用部分；已经有 React Three Fiber、现成场景组件或其他栈时，沿用其生命周期和所有权。普通表单、阅读排版和 CSS 焦点修复不加载本路线。四类能力不是一页必须集齐的效果配额。

## 1. 先选体验，再选技术

| 任务 | 先决定 | 看得见的完成条件 |
|---|---|---|
| 产品与空间质感 | 主体轮廓、现实尺度、材料角色、主光与反射来源；总览和特写各看什么 | 最终尺寸中能区分所需材料，结构与接触关系可信；换材质/对象有对应结果，窄屏保留关键轮廓与操作 |
| 镜头叙事 | 用户如何推进，镜头抵达何处，角色/短句/视频何时对应，怎样回退 | 按正常速度看镜头、内容与控制的节奏；快速前后切章、中断和重播后仍到达正确状态 |
| 探索与交互 | 探索的价值、移动/选择/阅读的输入归属、碰撞范围、直接内容入口 | 能理解所在位置和可做的事；物理反馈对应操作；能快速访问作品，退出阅读/迷路/翻转后能恢复 |
| 抽象与模拟 | 作用区域、输入→反馈、体积/惯性/光效怎样服务内容；是物理模拟还是艺术化近似 | 鼠标或触摸引起可辨的局部变化，释放后有合理演化；文字和主操作仍可用，静止/减少运动路径保留信息 |

参考机制各取所需：Showroom 的材料/自然光/尺度；Storybook 的镜头/角色/对白；Bruno 的驾驶/碰撞/地图与内容访问；Fluid Particles 的体积/惯性/即时反馈；AKARI 的光效/遮挡/颜色。AKARI 作者明确是 **2D** 光线实验，Fluid 的已确认依据是 WebGL；不据此推断它们采用 Three.js 或具有 3D 场景漫游。案例配色、控制和参数不成为通用模板，也不授予模型/纹理/代码的再使用许可。

## 2. 开工所需的最小技术合同

把未知项写成待核对事项，不用示意球、poster 或技术名称掩盖任务对象缺失。

- **版本与入口**：沿用项目锁定的 `three` 版本；core、addons、解码器与后期链来源相容。区分 WebGLRenderer 的 GLSL/EffectComposer 路线与 WebGPU/TSL 路线，按该版本官方接口实现，不混抄两套输出/材质代码。
- **对象与资产**：哪些部件/细节必须真实存在，模型来自谁、单位/朝向/原点/包围范围/UV/法线怎样核对；模型、贴图、环境图、动画和声音分别有许可。复杂产品需要合适资产或明确建模过程，组合基本体只在其造型确实满足任务时成立。
- **模式与状态**：只列当前路径需要的加载、可操作、聚焦、返回、暂停、失败、恢复、销毁状态。分别标记用户最新意图、正在过渡和已经抵达，DOM 文字/焦点/禁用状态与之对应。
- **实际预算**：记录下载字节、纹理尺寸/格式、可见实例/三角形和 draw calls、首个可操作等待及交互负担；根据目标设备和主体决定预算。网络压缩小不等于 GPU 内存小：例如未压缩 RGBA8 的 4096² 纹理约 64 MiB，完整 mip 链还会增加占用；具体格式分别估算。

只对导入模型启用资产解码分支，只对含镜头/章节的体验建立相应过渡控制；纯 2D shader 无需 GLB、空间碰撞或自由相机。

## 3. 产品质感：先让资产和颜色正确，再形成美术方向

**导入时先排资产错误。** 用 `GLTFLoader` 读取 glTF/GLB，核对场景节点、材料、动画、尺寸与朝向；需要时在合适查看器中对照。按文件实际扩展接入 Draco / Meshopt / KTX2 支持，解码器和转码器资源也必须在部署后可访问。KTX2 的设备支持检测按实际 renderer/版本完成。未使用某种压缩就不追加其依赖；加载进度不伪造为未知总量的百分比。加载失败时，依赖该资产的旋转、部位、材料等控制进入明确的不可用状态，重试后重新核对资产和控制。

**颜色与数据有不同职责。** 颜色/发光贴图通常标注 sRGB，normal、roughness、metalness、AO 等数据贴图保持数据语义；glTF 导入器已有的设置不要再次错误转换，手动换贴图时核对 UV、朝向和相同语义。照明与合成在合适的线性空间中进行，面向屏幕的最终输出只执行正确的一次显示转换。使用后期时由该管线的最终输出步骤承担，避免缺失或重复转换。模拟状态、速度、法线和中间计算纹理不做显示色彩转换。这一原则同样适用于 2D / shader，并不以是否有 glTF 为条件。自写 ShaderMaterial / RawShaderMaterial 的 fragment 输出也要核对：仅设置 renderer.outputColorSpace 并不代替 shader 中需要的输出步骤，按该版本使用 tonemapping_fragment、colorspace_fragment 或等价最终 pass；数据 pass 不加入显示转换。[官方颜色说明](https://threejs.org/manual/pages/color-management.html)

**材料、几何和光一起判断。** 先用中性光核对，再建立当前作品的光线主线。依主体选择 Standard / Physical 等材料；玻璃透射、厚度、clearcoat 等只在对象与预算需要时增加。PBR 材料需有可解释的环境反射/照明，按来源正确预处理环境；PMREM 是一种相应工具，不把环境亮度、曝光或粗糙度固定成全站常数。软硬边、倒角、法线/切线、贴图尺度和接触阴影在总览与特写中共同观察。曝光不能修复错误色彩链，bloom 也不能代替几何或材质细节。[材料](https://threejs.org/docs/pages/MeshPhysicalMaterial.html) · [环境预处理](https://threejs.org/docs/pages/PMREMGenerator.html)

若材质看起来像同一块塑料，先区分是贴图/法线/尺度、环境与高光、模型结构还是输出链的问题，再改有证据的一项。风格化作品可以选择非写实材料，验收仍看主体和表达是否成立。

**用高光说明形体。** 在完整构图中看外轮廓、转折面和接触点，为主光、环境反射、背景分别分配职责。弧面需要可读的高光走向，大平面需要足够宽的反射梯度；先改反射面的形状和位置，再调粗糙度。黑色主体沉没时分清背景同值、反射不足、法线或灯位问题，避免只加环境光把形体照平。主光确定体积，辅光和轮廓光只补当前缺口，灯数与强度不固定成模板。

**给材料一个可见特征。** 例如宽而柔的反射、狭长高光沿曲面滑动、涂层和底层不同的高光宽度；在相同中性环境与镜头下比较，再加入品牌光线。若边缘仍像纸片，先补真实厚度、倒角与法线，噪声贴图不会改变轮廓。clearcoat、transmission、sheen、anisotropy只为所需差异启用，检查像素成本，不以参数数量证明质感。

**接触感分清实现。** 动态投影、深度接触阴影和模糊blob能力不同；静物的轻量近似在升高或灯位改变后可能失效。先收紧阴影相机覆盖，再提高贴图尺寸，bias只做小量修正以免漂浮。RectAreaLight可提供矩形照明/反射但不投影，需要相应版本的初始化；环境反射也不自动提供空间遮挡。没有HDR时，可用同版现成RoomEnvironment或自建环境Scene经PMREM建立诊断环境，最终光线仍按画面决定。[RectAreaLight](https://threejs.org/docs/pages/RectAreaLight.html)

## 4. 镜头与叙事：进度、抵达、内容共用状态

持续世界连接正文/近看并需要跨段返回时，按[场景与内容连续衔接](scene-content-continuity.md)核对完整取景与目标关系；相机position相同不代表接管画面相同。内容重排、多个进度区间与暂停时钟也按该参考的实际选择处理。

同一图形需要从平面接进空间，或3D层必须与DOM对位时，读[投影与内容窗口](projection-and-dom.md)：先定保留的屏幕关系，再选择距离/FOV/zoom和局部裁切，不直接切两台相机或按窗口宽猜位置。

按主体包围范围和当前构图决定 target、视距/FOV、near/far 与安全余量；不要只用固定相机坐标适配所有模型。容器尺寸变化时更新实际 aspect、投影与相关 render target / composer；手机可重选镜头和版式，不只缩小 canvas。

滚动、章节、按钮与视频对齐到一份明确状态。区分动画进度与“抵达后可读/可操作”的条件；快速切换时取消或替代旧过渡，最后意图生效，旧回调不能把当前章节或相机写回过期值。沿曲线/受控轨迹移动时检查路径中的穿模和主体裁切，两个端点正确不等于中段正确。

位置、注视目标、路径和时间分别设计：每个镜头先说明抵达后要看清的关系。相机沿弧线移动不代表target也要绕圈，检查运动中段的轮廓、背景与阅读区。连续跟随按秒推进阻尼，避免每帧固定lerp比例；确定终点的章节镜头使用有限时长进度和明确完成条件，不让无限趋近阻塞下一步。相机所有权和完整姿态接管按[取景交接](scene-content-continuity.md#取景交接保留完整画面)。游戏镜头的碰撞、死区或摇屏只在探索任务确有需要时采用。

视频贴图等媒体先等就绪，再执行该次意图；元数据未知时保留待执行的 seek/播放意图，过期意图被取消。返回时停止当前放映/声音并回到合理总览；连续点击、动画中返回、重播、宽度变化和隐藏页签后仍能继续。对白/文字要有正常速度下的阅读时间，长内容提供直接回看路径。具体节奏服务内容，不能为了展示所有特效强行拉长路径。

## 5. 探索与输入：可玩，也能到达内容

当世界同时承担身份、空间导航和阅读入口时，参照[三站方法与迁移边界](immersive-world-motion.md)，选择当前任务需要的输入类别、跟随/手动查看交接、分层恢复和资产变体合同；不要求展品查看器引入驾驶物理。

场景视觉对象、碰撞体和可交互目标职责分开：碰撞代理可以简化，但不能明显穿过关键物件或阻断入口。需要持续模拟时采用适合的时间步/积分策略，控制恢复后的大时间差；不把一次离屏恢复后的巨大位移当正常反馈。驾驶/角色操作提供迷路、翻转或越界后的可找回路径，直接项目列表/地图可和探索共存。

指针拾取按当前 canvas 的 CSS 边界归一化坐标；滚动、缩放、DPR、布局变化后仍须命中真实对象。把轻点、拖动、阈值、取消/失焦和页面滚动分清。WASD/快捷键只在相应模式和焦点下生效，不拦截表单输入或穿透阅读层。触摸方案按任务设计，不能让 hover、双指或桌面键盘成为唯一退出方式。DOM 负责稳定的名称、说明、焦点与等价入口，热点负责空间指向。

按当前路径验证“探索→命中→聚焦内容→退出→恢复位置/相机/焦点”；只验证开车或视角能动，不能证明用户已经找到或读到内容。

换材料时，当前镜头应看得到所改变的表面与高光；聚焦部位时，镜头、热点和DOM说明指向同一个部位。手机可以换视点、缩短舞台、把文字移到场景前后，少量动作使用“看细节”“回总览”“表面”等任务语言。工程参数留给开发诊断，不把所有3D页面统一成模型加控制台。

## 6. 流体、粒子与光效：计算数据和最终画面分开

先明确艺术化近似、真实模拟或两者组合；不能用播放影片或一组随机抖动粒子冒充用户要求的实时流体反馈。原型先证明输入、演化/回弹和内容关系，再扩大粒子数或增加多 pass。

先写哪种输入作用于何处、影响半径/强度和释放后的演化，再选shader。Fresnel可强调视角相关边缘，位移可表示表面反馈，dissolve可承担显露/消退；围绕当前内容或命中点发生，不因机制可用就在全页叠加。Fresnel的法线与视线须处于同一空间，均匀缩放的法线片段不直接用于非均匀缩放。顶点位移需考虑细分、变形法线、包围范围与阴影深度路径；仅改可见顶点不能证明真实投影也跟随。[ShaderMaterial](https://threejs.org/docs/pages/ShaderMaterial.html) · [Object3D](https://threejs.org/docs/pages/Object3D.html)

后期先与无后期基线比较：Bloom不吞轮廓，景深不模糊要比较的部件，AO不把缝隙染成黑块。检查额外场景渲染、render target尺寸和全屏采样；选择性bloom也可能再渲染一遍场景，renderer的antialias不保证composer离屏缓冲已抗锯齿。是否保留由当前画面收益与真实设备表现决定。

- 输入坐标、速度与影响半径应随实际画布范围映射；移动快慢、拖动/释放、边界和暂停恢复产生可解释反馈。需要体积时实看遮挡、深度与轮廓，不以粒子数量代替体积感。
- GPGPU / ping-pong 计算用状态纹理与明确的读写次序，当前目标不同时作为同一步输出；格式、过滤和设备支持按 renderer/版本核对。数据 render target 保持数据，显示色彩转换只在最终呈现发生。使用 `GPUComputationRenderer` 等工具时处理初始化失败，并追踪其分配资源的释放。[官方工具](https://threejs.org/docs/pages/GPUComputationRenderer.html)
- CPU 或 GPU 由对象数、模拟需求和目标硬件决定，不把 WebGPU、物理库或重型模拟当默认依赖。透明叠加、后期 pass、分辨率和填充率也可能成为瓶颈，不能只数三角形。热点效果可局部降低质量或按需更新，文字与主操作保持清楚。
- 光效先决定发光源、遮挡边界、色彩面积与焦点；检查关闭/降低效果后主体能否辨认。后期只服务主线，正确完成最终输出与 resize，重建/退出时释放自己持有的 pass / render targets。[后期管线](https://threejs.org/manual/pages/post-processing.html)

## 7. 循环、失效与资源所有权

多个内容窗口共用canvas时，按[投影与内容窗口](projection-and-dom.md)区分完整viewport和可见scissor，使用实际CSS边界并在布局变化后重新测量。一个canvas仍可能有多个pass；按需循环应在过渡/输入变化时持续唤醒、落定后收束，不以架构名称代替预算核验。

每个活动实例有一个可解释的时钟/渲染所有者；依宿主采用按需 render、动画循环或 XR `setAnimationLoop`，不在按钮、滚动和 resize 中不断叠加循环。阻尼、模拟、视频/动画持续变化时需继续更新；静止的产品查看可以按需渲染。[按需渲染](https://threejs.org/manual/pages/rendering-on-demand.html)

WebGL 初始化失败或 context lost 时停止依赖失效上下文的更新，保留可读内容/返回/重试。按锁定版本核对资源重建与释放的时序，避免恢复后再通过旧监听器操作上一代 GPU 句柄；PMREM、计算目标等需重建的资源分别处理。恢复后核对资源、选择与相机状态，并重新实测计算结果；用真 context loss 或仅派发事件测试时分清证据范围，后者不能证明 GPU 资源真的重建。静态封面/文字是明确的替代路径，正常能力与替代版分别标注，不把替代图写成实时通过。

退出/卸载时取消该实例的动画、输入和监听，按所有权处理 geometry、material、texture、render target、controls、mixer 等。`scene.remove()` 不释放 GPU 资源；材质释放也不代替纹理释放。共享/缓存资产由所有者或引用计数管理，不能销毁宿主共用 renderer 或仍在使用的纹理；确由本实例持有的 ImageBitmap 也需相应处理。重进一次并观察资源基线是否稳定；内部缓存不必归零，不以一次内存数字证明没有泄漏。[官方释放说明](https://threejs.org/manual/pages/how-to-dispose-of-objects.html)

## 8. 把验收绑定到当前任务

在设计执行单中，只为选中的路线填写“想呈现的结果、核心操作、技术观察、完整构图/窄屏、未测项”。区分素材/渲染正确、美术判断、交互成立、性能观察与本人效果接受；技术成功或同意参考重点不代表未来作品已被接受。

| 适用路线 | 最小有意义证据；依实际风险增补 |
|---|---|
| 产品 | 资源身份与材质语义；总览/特写和所需换材质；自然光/反射/接触关系的实际画面；窄屏对象—控制—解释关联 |
| 叙事 | 正常速度的镜头/文字/媒体对应；前后切换、动画中返回、重播后的正确抵达；关键中段与窄屏取景 |
| 探索 | 实际移动/选择反馈；内容直接入口、聚焦/退出、复位与相应焦点；相关碰撞和输入取消/表单隔离 |
| 抽象 | 真输入对输出的响应与释放后演化；计算/显示分离；内容可读、暂停/减少运动、当前设备运行观察 |

复用未变化作品和当前源字节的有效证据；只因新改动、真实失败或具体疑点补测。用实际运行帧时间/连续观察判断表现，draw calls、一次 RAF 计数或视频解码帧数不能单独证明持续流畅。动态交审保留正常速度完整界面与关键状态；canvas 导出不冒充全 UI，脚本控制不冒充本人输入。优先用宿主可用工具完成观察与保存，仅在确需本人手势/选择且无法代理时请求；环境缺能力则保留未测，不反复让用户代做可自动完成的工作。
